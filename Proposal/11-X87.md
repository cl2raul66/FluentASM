# 11 — x87

> **Normativo.** La unidad x87 sigue presente en todo x64. FluentASM la expone como una **pila de 8 posiciones** (`Xrf0`–`Xrf7`), no como ocho registros planos.

---

## 1. Modelo físico

### 1.1 La pila

```
        TOP = 5
          │
          ▼
Xrf0  ┌─────────┐  ← ST(0)  tope lógico
      │ 80 bits │
Xrf1  ├─────────┤
Xrf2  ├─────────┤
Xrf3  ├─────────┤
Xrf4  ├─────────┤
Xrf5  ├─────────┤  ← posición física 5
Xrf6  ├─────────┤
Xrf7  └─────────┘
```

- Ocho celdas físicas de **80 bits** (1 signo + 15 exponente + 64 significando).
- Un puntero `TOP` de 3 bits en `Xrf.status` (bits 13–11).
- `Xrf0` es siempre el **tope lógico**, no la celda física 0.
- Un `push` decrementa `TOP`; un `pop` lo incrementa.

### 1.2 Por qué una pila

El hardware direcciona los operandos como `ST(i)`, es decir, **posición relativa al tope**. Modelarlo como registro plano obligaría al programador a llevar la cuenta de `TOP` mentalmente. Modelarlo como pila hace que `Xrf0` sea siempre "el valor de arriba", que es lo que el programador quiere.

---

## 2. Nombres y vistas

| Nombre | Legacy | Ancho | Uso |
|---|---|---|---|
| `Xrf0`–`Xrf7` | `ST(0)`–`ST(7)` | 80 | Posiciones de la pila |
| `Xrf.status` | `FSW` | 16 | Estado y `TOP` |
| `Xrf.control` | `FCW` | 16 | Control de precisión y redondeo |
| `Xrf.tag` | `FTW` | 16 | Etiquetas de ocupación |

`MM0`–`MM7` (MMX) están **prohibidos** → `FASM3073`.

---

## 3. Carga y almacenamiento

| Verbo | Sintaxis | Instrucción |
|---|---|---|
| `loadFloat` | `Xrf.loadFloat(Byte:4 [x])` | `FLD m32fp` — `D9 /0` |
| `loadFloat` | `Xrf.loadFloat(Byte:8 [x])` | `FLD m64fp` — `DD /0` |
| `loadFloat` | `Xrf.loadFloat(Byte:10 [x])` | `FLD m80fp` — `DB /5` |
| `loadInt` | `Xrf.loadInt(Byte:2 [x])` | `FILD m16int` — `DF /0` |
| `loadInt` | `Xrf.loadInt(Byte:4 [x])` | `FILD m32int` — `DB /0` |
| `loadInt` | `Xrf.loadInt(Byte:8 [x])` | `FILD m64int` — `DF /5` |
| `loadBinary` | `Xrf.loadBinary(Byte:10 [x])` | `FBLD m80dec` — `DF /4` |
| `storeFloat` | `Xrf0.storeFloat(Byte:8 [x])` | `FST m64fp` — `DD /2` |
| `storeFloatPop` | `Xrf0.storeFloatPop(Byte:8 [x])` | `FSTP m64fp` — `DD /3` |
| `storeInt` | `Xrf0.storeInt(Byte:8 [x])` | `FIST m64int` — `DF /2` |
| `storeIntPop` | `Xrf0.storeIntPop(Byte:8 [x])` | `FISTP m64int` — `DF /3` |
| `storeBinaryPop` | `Xrf0.storeBinaryPop(Byte:10 [x])` | `FBSTP` — `DF /6` |
| `copy` | `Xrf0.copy(Xrf1)` | `FLD ST(i)` / `FST` |
| `exchange` | `Xrf0.exchange(Xrf1)` | `FXCH ST(i)` — `D9 C8+i` |
| `duplicate` | `Xrf0.duplicate()` | `FLD ST(0)` |
| `free` | `Xrf0.free()` | `FFREE ST(i)` — `DD C0+i` |
| `freeAll` | `Xrf.freeAll()` | `FFREE ST(i)` × 8 |
| `rotateUp` | `Xrf.rotateUp()` | `FINCSTP` — `D9 F7` |
| `rotateDown` | `Xrf.rotateDown()` | `FDECSTP` — `D9 F6` |
| `pop` | `Xrf.pop()` | `FSTP ST(0)` |

Reglas:

- `Byte:N` debe ser 4, 8 o 10 para `loadFloat`/`storeFloat`; 2, 4 u 8 para enteros → `FASM3074`.
- `XrfN` para `N > 0` no es destino de `loadFloat`: la carga siempre empuja al tope.
- `store*` solo sobre `Xrf0` (el hardware solo almacena desde el tope) → `FASM3075`.

## 4. Constantes de hardware

La x87 provee constantes sin que el programa las escriba:

| Verbo | Instrucción | Constante |
|---|---|---|
| `Xrf.pushOne()` | `FLD1` — `D9 E8` | 1.0 |
| `Xrf.pushZero()` | `FLDZ` — `D9 EE` | 0.0 |
| `Xrf.pushPi()` | `FLDPI` — `D9 EB` | π |
| `Xrf.pushLog2OfTen()` | `FLDL2T` — `D9 E9` | log₂(10) |
| `Xrf.pushLog2OfE()` | `FLDL2E` — `D9 EA` | log₂(e) |
| `Xrf.pushLog10Of2()` | `FLDLG2` — `D9 EC` | log₁₀(2) |
| `Xrf.pushNaturalLogOf2()` | `FLDLN2` — `D9 ED` | ln(2) |

Estas constantes **las produce el hardware**: el fuente no contiene sus dígitos. Es el mismo caso que `Cpu.readTimestamp`: el programa no fabrica el dato, lo recibe.

## 6. Comparación

La x87 no tiene un flag de comparación directo: escribe los bits `C0`–`C3` de `Xrf.status` y, en las variantes `POP`/`COM`, también los flags del `Frf`.

| Verbo | Sintaxis | Instrucción | Resultado |
|---|---|---|---|
| `compare` | `Xrf0.compare(Xrf1)` | `FCOM` — `D8 D0+i` | `C0–C3` |
| `comparePop` | `Xrf0.comparePop(Xrf1)` | `FCOMP` — `D8 D8+i` | `C0–C3`, pop |
| `comparePopTwice` | `Xrf0.comparePopTwice(Xrf1)` | `FCOMPP` — `DE D9` | pop ×2 |
| `compareInteger` | `Xrf0.compareInteger(Byte:4 [x])` | `FICOM m32int` | `C0–C3` |
| `compareFloatAndSetFlags` | `Xrf0.compareFloatAndSetFlags(Xrf1)` | `FCOMIP` — `DF F0+i` | `ZF PF CF`, pop |
| `compareIntegerAndSetFlags` | `Xrf0.compareIntegerAndSetFlags(Byte:4 [x])` | `FICOMIP` | `ZF PF CF` |
| `test` | `Xrf0.test()` | `FTST` — `D9 E4` | compara con 0.0 |

Para usar `Frf` después de `compareFloatAndSetFlags`:

```fasm
Xrf0.compareFloatAndSetFlags(Xrf1)
Ipr.flowJump(@mayor if Frf.above)      // ST(0) > ST(1)
Ipr.flowJump(@igual if Frf.zero)
```

## 7. Trascendentes

| Verbo | Instrucción | Rango |
|---|---|---|
| `sin` | `FSIN` | \|x\| < 2⁶³ |
| `cos` | `FCOS` | \|x\| < 2⁶³ |
| `sincos` | `FSINCOS` | \|x\| < 2⁶³; deja seno y coseno |
| `tangent` | `FPTAN` | \|x\| < 2⁶³ |
| `arctangent` | `FPATAN` | — |
| `partialArctangent` | `FPTAN` variante | — |
| `power` | `FYL2X` / `F2XM1` | composición documentada |
| `logarithmBase2` | `FYL2X` | — |
| `logarithmNatural` | `FYL2X` + `FLDLN2` | composición |
| `exponential` | `F2XM1` + `FSCALE` | composición |

Las operaciones compuestas (potencia, exponencial) se expanden y la expansión se documenta (D-012). Usan solo `Xrf0` y `Xrf1`, declarados.

## 8. Control y estado

### 8.1 Palabra de control (`Xrf.control`)

| Bits | Campo | Valores |
|---|---|---|
| 0 | IM | máscara de inválido |
| 1 | DM | máscara de denormal |
| 2 | ZM | máscara de división por cero |
| 3 | OM | máscara de overflow |
| 4 | UM | máscara de underflow |
| 5 | PM | máscara de precisión |
| 8–9 | PC | precisión: 24, 53, 64 bits |
| 10–11 | RC | redondeo: nearest, down, up, zero |
| 12 | X | infinito afín (obsoleto) |

```fasm
Gpr0.low16.copy(Xrf.control)          // FNSTCW [mem] + load
Xrf.control.copy(Gpr0.low16)          // FLDCW [mem]
Xrf.control.precision(.extended)      // azúcar de .bit(...)
Xrf.control.rounding(.nearest)
```

### 8.2 Palabra de estado (`Xrf.status`)

| Bits | Campo |
|---|---|
| 0 | IE — inválido |
| 1 | DE — denormal |
| 2 | ZE — división por cero |
| 3 | OE — overflow |
| 4 | UE — underflow |
| 5 | PE — precisión |
| 6 | SF — stack fault |
| 7 | ES — error de pila |
| 8 | C0 |
| 9 | C1 |
| 10 | C2 |
| 11–13 | TOP |
| 14 | C3 |
| 15 | B — busy |

```fasm
Gpr0.low16.copy(Xrf.status)           // FNSTSW AX
Xrf.status.clear()                    // FNCLEX
```

> Las versiones sin espera (`FNSTSW`, `FNSTCW`, `FNCLEX`, `FNINIT`) son las que emite el compilador. Las variantes con espera (`FSTSW`, `FSTCW`) esperan a que termine la instrucción anterior y son más lentas.

### 8.3 Palabra de etiquetas (`Xrf.tag`)

Indica qué celdas están ocupadas (00 válida, 01 cero, 10 especial, 11 vacía). Se consulta con `FNSTENV`; el lenguaje la expone como lectura:

```fasm
Gpr0.low16.copy(Xrf.tag)
```

## 9. Verificación de profundidad

El compilador mantiene un contador de profundidad por bloque básico:

| Verbo | Δ profundidad |
|---|---|
| `loadFloat`, `loadInt`, `pushOne`, `pushZero`, … | +1 |
| `duplicate` | +1 |
| `sincos` | +1 |
| `storeFloatPop`, `storeIntPop`, `pop`, `free` | −1 |
| `addFloatPop`, `subFloatPop`, `multiplyFloatPop`, `divideFloatPop` | −1 |
| `comparePop` | −1 |
| `comparePopTwice` | −2 |
| `compareFloatAndSetFlags` | −1 |
| `exchange`, `addFloat`, `multiplyFloat` | 0 |

- Profundidad > 8 → `FASM3071` (error: desbordamiento de pila).
- Profundidad < 0 → `FASM3072` (error: subdesbordamiento).
- Profundidad ≠ 0 al terminar el camino → `FASM3076` (advertencia; puede ser intencional).
- Si el flujo se une con profundidades distintas → `FASM3077`.
- `rotateUp`/`rotateDown` invalidan el análisis → `FASM3078`.

## 10. x87 en el mundo moderno

| Aspecto | Recomendación |
|---|---|
| Cálculo FP nuevo | Use `Simd.r128.part{32/64}` (SSE/AVX) |
| Precisión de 80 bits | x87 es la única opción |
| BCD | `loadBinary`/`storeBinaryPop` |
| Trascendentes | x87 tiene `FSIN`/`FPATAN`; AVX-512 no |
| Mezcla con SSE | Evite `MMX`; si usa `MMX`, `EMMS` al salir |

El lenguaje permite x87 completo porque es hardware real, pero documenta que es la vía lenta y no la recomendada.

## 11. Diagnósticos x87

| Código | Situación |
|---|---|
| `FASM3070` | `XSETBV` fuera de ring 0 |
| `FASM3071` | Desbordamiento de pila x87 |
| `FASM3072` | Subdesbordamiento de pila x87 |
| `FASM3073` | Uso de MMX |
| `FASM3074` | Ancho de memoria inválido para el verbo |
| `FASM3075` | `store*` sobre `XrfN` con `N ≠ 0` |
| `FASM3076` | Pila no vacía al final del camino |
| `FASM3077` | Profundidades incompatibles en una unión de flujo |
| `FASM3078` | `rotateUp`/`rotateDown` impide el análisis |
| `FASM3079` | Excepción FP no enmascarada en `Xrf.control` |

## 12. Ejemplo

```fasm
routine hipotenusa.abi(win64).returns(Gpr) {
    parameter a: Gpr
    parameter b: Gpr

    Byte:8 [ladoA].copy(a)
    Byte:8 [ladoB].copy(b)

    Xrf.loadFloat(Byte:8 [ladoA])       // st0 = a
    Xrf0.multiplyFloat(Xrf0)             // st0 = a²
    Xrf.loadFloat(Byte:8 [ladoB])       // st0 = b, st1 = a²
    Xrf0.multiplyFloat(Xrf0)             // st0 = b², st1 = a²
    Xrf1.addFloatPop(Xrf0)               // st0 = a² + b²
    Xrf0.squareRoot()
    Xrf0.storeFloatPop(Byte:8 [resultado])

    Gpr0.copy(Byte:8 [resultado])
    Ipr.flowStackJump()
}
```

## 13. Resumen

- `Xrf0`–`Xrf7` son posiciones de una pila, no registros planos.
- `TOP` es implícito y se consulta en `Xrf.status`.
- Cargar empuja; almacenar desde el tope.
- Las constantes (π, e, log₂) las produce el hardware.
- Los flags de comparación son `C0`–`C3` o, con `FCOMIP`, `Frf`.
- La profundidad se verifica estáticamente.
- MMX está prohibido.
